Arquitectura políglota de TiendaYa

Un frontend Vue habla con una API Flask dividida en 14 Blueprints. Seis componentes de persistencia, cada uno con un rol: PostgreSQL decide si hubo compra; MongoDB es la fuente de verdad del catálogo; Redis guarda lo transitorio; Elasticsearch, Neo4j y pgvector son proyecciones derivadas que se reconstruyen si se pierden. No hay commit en dos fases: las copias se reintentan por un outbox.

1. Vista general

Cada flecha hacia un motor lleva el usuario con que se conecta. Desde la entrega final, Redis no acepta conexiones anónimas y cada servicio entra con un usuario distinto.

2. Checkout distribuido: idempotencia, transacción y outbox

El checkout toca cuatro motores y ninguna transacción los abarca a todos. Lo que pasa antes del COMMIT se compensa. Lo que pasa después se completa con reintentos y nunca se deshace. Desde la entrega final, el relevo entra a Redis con su propio usuario, que solo puede leer y borrar líneas de carritos y reservas.

3. Recomendación y búsqueda semántica (nuevo)

pgvector solo guarda vectores y responde «estos productos se parecen, con esta similitud». Los datos que se muestran salen de MongoDB. El modelo de lenguaje solo se necesita para convertir texto en vector: al guardar un producto y al buscar por frase; los productos relacionados comparan vectores ya guardados.

Por qué cada motor

PostgreSQLPedidos, pagos e inventario necesitan ACID y bloqueo de filas. Es lo único que decide si hubo compra (ADR-005: no migrar pagos a NewSQL).
MongoDBEl catálogo tiene atributos distintos por categoría y un historial de cambios por producto como registro de eventos.
RedisCarrito y ofertas flash: datos transitorios, con TTL y scripts Lua atómicos para no sobrevender el cupo (ADR-003).
ElasticsearchBúsqueda tolerante a errores de tipeo, facetas y autocompletado, que MongoDB no resuelve bien (ADR-004).
Neo4jLos patrones de fraude son recorridos de varios saltos entre cuentas, productos, vendedores y direcciones (ADR-002, ADR-007).
pgvectorSimilitud semántica de las descripciones: vecinos más cercanos sobre embeddings, con SQL y un índice HNSW (ADR-008).
